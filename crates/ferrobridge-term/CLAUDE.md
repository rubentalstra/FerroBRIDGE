# ferrobridge-term

The hand-written FHIR terminology client. The oracle is the HL7 FHIR
specification for the release in play: the `OperationDefinition` of each
operation under `tools/fhir-codegen/vendor/hl7.fhir.r4.core` and
`hl7.fhir.r4b.core` for every parameter, and the operations framework
(<https://hl7.org/fhir/R4/operations.html>) for the invocation and the failure
shape.

- **The contracts come from `fhir-types`, never from hand-written JSON.**
  `fhir_types::r4::operations` and `fhir_types::r4b::operations` carry the
  request and response types with `from_parameters` and `into_parameters`. A
  shape that is wrong or missing is a generator fix, never a local type
  (`.claude/rules/codegen.md`).
- **One module per release, generated by the `per_release` macro in
  `wire.rs`.** R4 and R4B declare identical parameter sets for the three
  operations, so the macro body is written once and the release decides only
  which generated model reads the body. Verify any claimed per-release
  difference against both vendored `OperationDefinition` files before encoding
  it.
- **A negative answer stated in `out` parameters is an outcome; a refusal is an
  error.** `LookupOutcome::NotFound`, `TranslateOutcome::NoMatch` and
  `ValidateOutcome::Invalid` are outcomes. Everything else keeps the upstream
  status and body in a typed error. Nothing is ever flattened into `None`, a
  default, or an empty display.
- **Which refusal means "not known" is our own decision**, flagged in
  `decode.rs`: no FHIR clause fixes the status or the issue code, so the client
  reads the `tx-issue-type` classification and falls back to a bare `404`.
  Change it only with a citation.
- **`translate` never decides for the caller.** Every match is returned with
  its equivalence; `accepted()` yields `equivalent` and `equal` alone. A
  refusal fails closed and is never a missing translation.
- **Retry covers connect failures, timeouts and `5xx` only**, and the `POST`
  form is retried because the three operations declare `affectsState: false`.
  The predicate is `Error::is_retryable` and it is tested.
- **The log carries the operation, the URL path and the status.** A code is a
  clinical fact: never log a body, a code, or a query.
- **Tests are `wiremock` contract tests through the testkit stubs**, one case
  per outcome and per error family, both releases per operation, plus the
  container run behind `FERROBRIDGE_E2E=1`. Every fixture is synthetic.
